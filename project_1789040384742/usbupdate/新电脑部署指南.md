# 新电脑独立部署指南

最新A/B模式已改为U盘自动识别：配置向导不再要求选包和填日期。将两个原名带完整日期的ZIP放在U盘USB_UPDATE以外的目录，运行时自动扫描、生成Update.zip，并按原包名日期核验QNX。详见 [U盘自动识别说明](U盘自动识别说明.md)。下文手动选包说明仅适用于未启用package_source=usb_scan的旧配置。

## A/B 压测配置向导

准备好 AutoCar Python 和 ADB 后，在 usbupdate 目录执行 `./configure_stress.ps1`，或 `./run_stress.ps1 -Configure`。两条命令均只配置，不启动升级；配置保存后再运行 `./run_stress.ps1`。压测配置文件不存在时，run_stress.ps1 也先进入向导，保存后退出。

向导读取已有配置或模板，选择是否冒烟、确认在线有线 ADB、U 盘根目录、COM、电源资源和 USB 通道，再弹窗选择 A/B ZIP。优先从包内明确 QNX 字段读取日期，读取不到则填写真实日期，绝不使用今天日期或文件修改时间代替。两包日期相同的情况不能通过本向导配置。保存前显示配置摘要，旧配置备份到 deployment_logs。取消不会覆盖原配置。

不冒烟自动使用 local_pair，会先缓存两个包到电脑；冒烟自动使用 usb_pair_smoke，要求两个原包在 U 盘且位于 USB_UPDATE 目录外，选择完整 ATS 工程，启动压测时再选用例。向导保留其他升级参数，只修改 usb_stress_config.json，不安装 SDK/驱动、不配置主升级的 config.json、不验证 ATS 扩展或实际电源通信。

例如：`Set-Location -LiteralPath 'D:\雷诺\usbupdate'`，然后执行 `./configure_stress.ps1`。COM 号、电源资源和物理通道需要人工确认，不能根据旧电脑配置认定连接正确。

本包是可迁移的 Windows Python 工程，不是免安装 EXE。所有升级协调模块、配置模板、ATS 连接扩展、辅助依赖清单、环境检查和说明都随包提供，不依赖原电脑用户名或原 D 盘路径。专有 SDK、硬件驱动、浏览器以及测试用例不打入包内。

## 推荐：一个入口完成部署

在解压后的 usbupdate 目录打开 PowerShell，执行：

```powershell
.\deploy_all.ps1
```

无需分别执行 deploy、setup 和 check_environment。按提示选择是否需要云盘、ATS 工程，并确认 ADB 序列号、盘符、串口、电源资源和分类。AutoCar Python 现在自动识别：依次检查 AUTOCAR_PYTHON、已保存 python.path.txt、当前用户 ATS 标准安装目录、已激活虚拟环境、工程 .venv/venv 和 PATH。候选必须通过 Python 3.10+、AutoCar、tkinter 的实际导入验证；失效路径跳过，首个可用路径自动保存。每个候选最多等待 20 秒，不全盘扫描。仅全部找不到时才要求手填，不会自动安装不明同名 AutoCar 包。可预先指定 `-PythonPath` 与 `-AtsProject`，其他信息按提示确认。

入口按顺序完成：

1. 验证公司 AutoCar SDK、Python 3.10+ 和 tkinter。
2. 安装 requirements-support.txt 中的公开 Python 依赖。
3. 优先复用现有 ADB，缺失时下载官方 Platform Tools。
4. 备份并更新两份配置的本机路径和硬件信息；保存 Python 路径；压测使用原 tests_scripts 并在启动时选择用例。A/B 包路径和日期保留，换电脑后仍需核对。
5. 缺少 VS Code 时通过 Windows winget 安装；检查公司 ATS 扩展，安装自带连接扩展 1.0.2。选云盘模式且缺少 Edge 时也通过 winget 安装。
6. 检查依赖、配置、原用例发现和有线 ADB 状态。
7. 若选择云盘模式，则继续初始化登录并等待扫码；本地压测模式跳过云盘。

最后显示 DEPLOYMENT COMPLETE 才表示上述检查通过，失败显示 DEPLOYMENT STOPPED 和具体原因。日志与配置备份位于 deployment_logs/；解决问题后重新运行同一个入口即可。该目录包含本机配置备份，不上传 GitHub。

无法由此脚本自动提供的前置条件：公司 AutoCar SDK/ATS 扩展、真实 ATS 测试工程、车机/USB切换器/电源驱动、硬件接线及供电参数。缺少 SDK/ATS 时会停止并提示，不会用网上同名包替代。缺少 winget 时需人工安装所提示的 Windows 应用后重试。自动下载需要网络及相应权限。

部署不会运行用例、刷写、格式化或开关电源。安装扩展后仍需在原 ATS 工程窗口执行 Developer: Reload Window；工作区信任、扫码授权等交互由用户完成。下面的分步命令保留用于排查。

## 1. 必须准备的工具与环境

| 项目 | 用途 | 获取/准备方式 |
|---|---|---|
| Windows 10/11 64 位桌面电脑 | PowerShell、USB 卷操作、ATS/Edge 窗口 | 保持用户登录和电脑不睡眠 |
| Windows PowerShell 5.1 / powershell.exe | 运行 ps1、格式化、安全弹出 | Windows 系统组件；需存储管理命令可用 |
| Python 3.10+ | 脚本运行 | 优先选择安装 ATS 后已有的 Python，或公司支持的 AutoCar 环境 |
| 公司 AutoCar SDK | AT、USB 切换、程控电源 | 从公司/ATS 正式渠道安装；不要 pip 安装不明同名包 |
| tkinter/Tcl/Tk | 首次本地包选择框 | Python 安装组件；不是 pip 包 |
| Android Platform Tools / adb.exe | 有线 ADB、版本读取和截图 | 已有 ADB 可配置完整路径；deploy -InstallAdb 可下载官方工具 |
| 车机 USB/ADB 驱动 | Windows 识别车机 | 设备厂家驱动；车机打开调试并授权此电脑 |
| USB 切换器串口驱动 | 控制 USB 路由 | 按切换器厂家提供驱动；新电脑 COM 号可能变化 |
| 电源驱动、SDK 所需 VISA/串口后端 | 程控电源输出开关 | 按电源型号及 AutoCar 环境安装，公司原工具能控制电源后再使用脚本 |
| Playwright Python 包 | 云盘自动化 | requirements-support.txt；本地压测不访问云盘 |
| Microsoft Edge | 云盘界面与下载 | 单独安装；默认 browser_channel=msedge，不需要另装 Playwright Chromium |
| uiautomator2 | UI dump 被占用时的后备读取 | requirements-support.txt，设备端服务须可用 |
| VS Code + AI Test Studio | 冒烟正式执行界面 | 安装公司 ATS 扩展和其支持的环境 |
| USB Upgrade ATS Bridge 1.0.2 | 从升级脚本打开 ATS 并提交新冒烟目录 | 随包 ats_bridge/*.vsix，安装后 Reload Window |
| pytest、allure-pytest | ATS 用例运行与报告 | requirements-support.txt；用例的其他依赖另按 ATS 工程安装 |
| 完整 ATS 测试工程 | page_objects、fixtures、真实冒烟用例、设备配置 | 从原项目或公司仓库迁移，不包含在本独立脚本包内 |
| Git、GitHub Runner | 仅使用 GitHub CI 时需要 | 普通本地升级/压测不需要 |

不强制安装 Node.js、Docker、Jenkins 或 Java 来运行升级脚本。VSIX 已打包；是否需要额外工具生成或查看 ATS 报告，以 ATS 项目自身要求为准。

支持依赖未做精确版本锁定；不要认定任意版本的 AutoCar/ATS 均兼容。建议复用已验收的公司 ATS 环境。对准备好的环境可执行 `python -m pip freeze` 留存依赖版本，迁移时仍按公司软件分发规则安装 SDK。这里没有捆绑或重新分发 AutoCar。

## 2. 硬件与目录

需要车机、独立有线 ADB、可移动 U 盘、USB 切换器、程控电源。电源电压/限流按车机规格由台架预先设置，脚本仅开关输出。USB 通道默认电脑 3、车机 2，但串口/资源名必须按实际设备核对。切换 U 盘时不能断开独立 ADB。

有 ATS 冒烟时，将部署包解压到 **ATS 工程根目录的 usbupdate 子目录**：

```text
任意路径/ATS项目/
├─ tests_scripts/          主升级冒烟
├─ page_objects/           原 ATS 页面对象及设备配置
├─ conftest.py             按项目需要
└─ usbupdate/
   ├─ deploy.ps1
   ├─ run.ps1
   ├─ run_stress.ps1
   ├─ config.example.json
   ├─ usb_stress_config.example.json
   ├─ smoke_cases/         U盘双版本压测冒烟
   └─ 其他随包模块
```

可换磁盘和工程名称，但使用 ATS 连接扩展时 usbupdate 这一层及日志位置应保留。只做升级而不冒烟时可以放在任意本地目录，并在配置关闭 smoke.enabled；usb_pair_smoke 模式始终要求冒烟，不支持关闭。

## 3. 新电脑初始化

1. 安装上述公司 ATS/AutoCar 和硬件驱动，确认其 Python 路径。
2. 用 PowerShell 进入新电脑 usbupdate 目录；格式化模式需要管理员权限。
3. 执行（路径换成新电脑真实位置）：

```powershell
.\deploy.ps1 -PythonPath 'C:/实际环境/Scripts/python.exe' -AtsProject 'D:/ATS项目' -InstallDependencies -InstallAdb
```

该命令验证 Python、AutoCar、tkinter，保存本机 python.path.txt，创建缺失的 config.json 和 usb_stress_config.json，安装辅助 pip 包及下载 ADB。已有配置不覆盖。若已有依赖和 ADB，省略两个 Install 开关即可。离线环境提前按公司方式安装依赖/工具，不使用下载开关。

解释器优先级为 AUTOCAR_PYTHON → 本目录 python.path.txt → 当前用户 APPDATA/iatset/venv → PATH 中 python。发现指定路径无效会报错，不静默忽略。换电脑需重新 deploy，不复制旧 python.path.txt。

若系统策略禁止执行可信 ps1，可按公司策略处理；在获准情况下可用当前进程范围 `Set-ExecutionPolicy -Scope Process RemoteSigned`，不要求改全机策略。

4. 编辑生成的两份配置（它们互相独立）：

| 字段 | 应填的实际值 |
|---|---|
| adb | tools/platform-tools/adb.exe，或已有 adb.exe 完整路径 |
| usb_serial | adb devices -l 中的目标车机序列号，模板占位符必须替换 |
| usb_root | 新电脑识别 U 盘的根盘符，如 F:/ |
| power.resource | 实际电源资源，如 ASRL13::INSTR，不保证新电脑相同 |
| usb_switch.port | 实际控制串口，如 COM14 |
| pc_usb_port / car_usb_port | 根据物理接线核对，默认 3 / 2 |
| smoke.project_root | 新电脑 ATS 工程根目录；deploy 只对新创建配置填入此路径 |
| cloud.path / variant | 项目分支目录及 GAS/no_gas 分类；使用云盘需登录权限 |
| stress.packages | 双版本包路径及对应 QNX 日期/完整版本 |

5. 把真实冒烟用例及依赖放到对应目录。usbupdate/smoke_cases 初始只有说明，无测试代码；需复制所需用例、资源及 fixture。tests_scripts 下的 conftest.py 不会自动作用于 smoke_cases。
6. 在 VS Code 中安装扩展：扩展面板 → “从 VSIX 安装” → 选择 ats_bridge/usbupdate-ats-bridge-1.0.2.vsix → Developer: Reload Window。保持新 ATS 根工程打开且受信任。
7. 执行只读检查：

```powershell
.\check_environment.ps1
```

检查 Python 模块、ADB 路径、配置及冒烟目录，不扫码、不格式化、不操作电源或连接车机。全部通过也不代表驱动和真机已验证；缺少本次不用的模式依赖仍可能报告，应按计划使用的功能补齐。

## 4. 运行

```powershell
.\run.ps1 check        # 主升级：选GAS/no_gas并扫码登录
.\run.ps1 ci-once      # 等当天包，升级+校验+冒烟一次，随后退出
.\run.ps1 auto         # 主升级：每天循环
.\run.ps1 local        # 已有本地包，单次升级及冒烟
.\run_stress.ps1       # 独立压测，读取usb_stress_config.json
```

云盘主升级会格式化配置 U 盘；本地双版本压测不会下载或格式化。把 A/B 原包提前放到 U 盘的 versions 等目录，不能放到 USB_UPDATE 中；脚本每轮复制为 USB_UPDATE/Update.zip。终端显示轮次，版本核验及 ATS 冒烟全部通过才进入下一轮，Ctrl+C 停止。ATS 正在运行时终端 Ctrl+C 不保证停止用例，还需 ATS 页面停止。

当两个版本日期相同时，请分别配置 expected_qnx 完整版本，避免仅日期核验无法区分版本。跨车型的软件组件名、UI 文字和定位配置可能不同，本包并非适配所有车机的通用刷机工具。

## 5. 不应随部署包复制的文件

不复制 `.auth`、真实 config.json、旧日志、daily_state.json、python.path.txt、安装包、缓存、设备识别数据库及旧机器 VS Code 设置。首次部署按真实环境生成。包内只含模板和源码，无云盘登录凭据。

本独立包可运行的前提是外部 SDK/硬件/ATS 依赖满足；本次仅完成代码和本地模拟验证，尚未在另一台电脑完成实机验收。
