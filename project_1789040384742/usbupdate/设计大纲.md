# U 盘升级设计大纲

## 自动模式增量

环境检查独立保留，新增 auto 统一编排其余步骤。auto_update.py 采用不交互状态机，volume.py 负责 Windows 锁卷/刷新/卸载/弹出；成功弹出之后才允许 USB 切换。车机端需读取包 SHA256 与下载结果匹配。任何失败均停止，不自动重试刷写或补发上下电。

check 统一检查依赖和云盘会话；会话无效则在此阶段等待扫码。登录后用新的浏览器会话验证可复用性，保存成功后才报告环境检查通过。auto 直接复用本机登录，认证过期时停止并提示重跑 check。目标 QNX 使用构建绑定映射或 ZIP 内明确的版本元数据，缺失/冲突即停止，不采用日期猜测。自动入口已完成，完整下载、硬件弹出与刷写未实跑。

2026-09-14 已验证自动导航到升级页和工程模式读取 QNX。当前工程模式 Overview 显示版本；使用已实测 Activity 入口绕过无法匹配的原文应用名。APK 默认资源明确指出第二步安装按钮为 Start Upgrade；校验、安装和激活状态分别为 Upgrade package verified、Installation complete、Activation complete。仅在激活完成与明确重启提示均存在时执行上下电。

## 1. 需求解读

默认 GAS（full_userdebug）。从创达云盘每日构建取得升级包，写入 U 盘 USB_UPDATE/Update.zip；通过有线 ADB 操作车机完成校验、刷写、激活，再用程控电源重启并核验 QNX。最新有线 ADB 要求替代最初材料中的无线方案。

硬件按截图及补充：电源 ASRL13::INSTR，USB 切换器 COM14，USB3 接电脑，USB2 接车机；独立有线 ADB 保持连接，已检测到设备 3696ade 在线。运行环境为 C:/Users/TS/AppData/Roaming/iatset/venv/Scripts/python.exe。

## 2. 流程

1. 使用已有 AutoCar Python 环境，检查 ADB、指定有线序列号及车机时钟。Wi-Fi 只用于时间同步。
2. [创达云盘](https://pan.thundersoft.com/web/index.html) 登录后，左侧群组文件 → ThunderGod → 01-DailyBuild → ThunderGod-a-14.0-qcom_r14.1-main-Asample。
3. GAS 为 full_userdebug；NO_GAS 为不含 full 的 userdebug。支持 update_all_renault.zip 实际文件名。按 YYYYMMDD_HHMMSS 构建时间选所选分类下现有最新日期，同日取最新时间，不要求当天；最新目录目标包缺失时停止，不回退早期包。
4. at.usb_switch(port="COM14", usb_port=pc_usb_port)，等待 Windows U 盘枚举。
5. 写 .part，flush/fsync、SHA256 与 ZIP CRC 校验通过后改名 Update.zip；记录构建和预期 QNX。不格式化、不覆盖旧包。
6. 人工安全弹出后，at.usb_switch(port="COM14", usb_port=car_usb_port)，检查电脑盘符消失、有线 ADB 在线，确认车机识别包。
7. 应用列表 → USBUpdating Btn → USB Upgrade。第一次 Start Update 校验，确认成功后第二次开始刷写。完成条件分开配置。
8. 刷写完成后 Activate。明确激活完成且提示重启，才进入电源阶段。
9. AT() → power_open("ASRL13::INSTR") → set_output(on=False) → 等待 5 秒 → set_output(on=True)。不设置电压、限流，不以 adb reboot 代替。
10. 等待有线 ADB 恢复，boot_id 发生变化且 sys.boot_completed=1。
11. ThunderSoft → Version Date Information → QNX system version，完整匹配预期版本。

## 3. 模块与状态

- usb_update.py：包选择、写入、ADB、UI、流程、版本和日志。
- hardware.py：延迟加载 AutoCar；USB 切换和电源上下电。plan 不构造 AT。
- cloud_download.py：基于已核对的网页控件自动导航、遍历、选包和下载，使用独立 Edge 会话，扫码登录不写入配置。
- config.example.json：设备、通道、超时、云盘路径、UI 选择器。
- packages.example.json：当前云盘适配输入，描述真实包源、日期、哈希、QNX。
- setup.ps1：检测依赖，可选安装官方 ADB，保留已有配置。

SDK 返回失败即停止。切换器 ACK 不等于磁盘已挂载，需另外检查枚举与现场状态。电源输出成功不等于设备已完成重启，需验证 boot_id 与启动属性。

## 4. 有线接线约束

用户已确认 ADB 独立连接，wired_adb_independent 已设 true。U 盘切到 USB2 后仍检查有线 ADB 在线，不回退无线模式。

## 5. 交付边界

已接入截图中的电源调用与公开参考里的 USB 切换接口，默认电源与串口已配置。单元测试覆盖 USB 通道、回读错误、上下电顺序/等待/失败、有线连接、包筛选与 UI 停止条件。

硬件通道、序列号、接线与 AutoCar 环境已确认，三个硬件接口已查询实际安装版注册表。登录后目录与下载菜单已核对，已生成自动下载实现，但未实跑完整大包下载。当前待填实际 U 盘盘符、目标 QNX 值及 UI 状态控件。

Windows 安全弹出、车机挂载确认、页面入口及未配置的状态仍需人工确认；没有无人值守或真机升级成功证据。云盘会话需用户扫码。下载包的本地 SHA256 只证明后续复制一致，不能替代发布方对该 ZIP 的签名或哈希。

## 6. 异常原则

无当天包、同日歧义、哈希错误、旧包存在、通道不合法/回读错误、ADB 断开、状态超时、未激活或版本不符均停止。刷写失败不自动断电、切走 U 盘或重刷；中断后不在 finally 中自动上电，按日志检查现场状态后处理。
