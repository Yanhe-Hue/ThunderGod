# U 盘升级、版本校验与 ATS 冒烟自动化

首次部署、迁移或排查依赖，请阅读 [环境依赖与配置说明](环境依赖与配置说明.md)，其中包含完整软件依赖、接线、全部配置字段、安装步骤及常见报错。

## U 盘升级循环压测（独立功能，不执行冒烟）

```powershell
.\run.ps1 stress
```

首次弹窗选择已有安装包，后续轮次复用同一个 `USB_UPDATE/Update.zip`。每轮自动执行：切到电脑并核对包未改变 → 安全弹出 → 切到车机并校验哈希 → 校验/安装/激活 → 下电 5 秒再上电 → 等待 60 秒 → 确认新 boot_id 和启动完成 → 校验 QNX 日期。每轮校验通过才进入下一轮，所有轮次均不运行 ATS 冒烟，不受 smoke.enabled=true 影响。

无需轮数或间隔参数，持续循环运行，按 `Ctrl+C` 手动停止。此功能不下载或格式化；电脑上选择的包在第一轮准备到 U 盘，之后复用。日期以压测启动当天固定为预期，跨午夜不会变成次日；新启动的压测重新取当天日期。

任一轮升级失败、包改变、日期不符、重启超时或用户中断即停止，不自动重刷或强行断电。压测要求每轮确实重新安装；若车机保留上轮“安装完成/激活完成”，或拒绝相同版本重复升级，则停止，不将跳过安装记为成功。

总日志目录下的 `stress_summary.json` 持续记录每轮状态、耗时、安装包哈希及该轮日志路径，轮数不限。手动停止记录为 `cancelled`，运行失败记录为 `stopped`。手动停止不会强行断电；若车机仍在刷写，应等待车机完成。本功能仅完成代码和模拟测试，尚未执行真实循环刷写。

只执行 ATS 冒烟：`.\run.ps1 smoke`。直接启动按编号排列的测试集，不检测日期、不升级、不上下电。安装连接扩展更新后，请先在 VS Code 执行 Developer: Reload Window，使当前窗口加载修复版扩展。

## ATS 正式执行页面（当前执行方式）

本机已安装 `USB Upgrade ATS Bridge` 连接扩展。请在 VS Code 中打开上述 ATS 工程根目录（不要只打开 usbupdate 子目录），保持工作区受信任且 AI Test Studio 扩展启用。

版本校验成功后，脚本生成按数字排序的 `USB_Smoke.set`，通过 `AutoTest.RunScripts` 命令直接交给 ATS。ATS 自己负责调度用例、显示执行页面和生成报告；升级脚本不再单独启动 pytest。终端每秒读取 ATS 的 run.log，实时显示用例输出；暂时无新输出时每 15 秒提示仍在执行。首次打开链接时若 VS Code 提示是否允许打开连接扩展，请允许。

命令保持不变，例如 `.\run.ps1 verify-adb` 会在日期校验成功后打开 ATS 执行页面并运行冒烟。`.\run.ps1 smoke-plan` 只查看计划。中止测试请使用 ATS 执行页面的停止按钮；Ctrl+C 只停止终端监看，不会停止 ATS。

当前报告位于 `logs/<时间>/smoke/`：`order.json` 为顺序，`USB_Smoke.set` 为 ATS 测试集，`ats-result.json` 为 ATS 返回结果，`ats-report/run.log` 为完整实时输出，`ats-report/allure-results` 及 `ats-report/reports` 为 ATS 生成结果。只有 ATS 返回完成且全部测试通过，脚本才报告成功。下文关于旧版逐文件独立 pytest、单文件超时和 JUnit 子目录的说明是旧执行器行为，当前由 ATS 管理这些事项。

## 2. 包含的功能

| 功能 | 行为 |
|---|---|
| 环境检查 | 检查 Python 依赖及 ADB 配置，登录云盘并保存可复用会话 |
| 云盘选包 | 弹窗选择 GAS/no_gas，只选择当天该分类最新时间的构建；缺少当天包则停止，不回退昨天或改用其他分类 |
| U 盘初始化 | auto 模式先确认当天该分类的唯一 Renault 包存在，再格式化配置的可移动 USB 盘为 exFAT，清除全盘文件 |
| 下载与准备 | 下载唯一 Renault 包，校验大小、ZIP CRC、SHA256，最终保存为 USB_UPDATE/Update.zip |
| 本地选包 | local 模式选择电脑或 U 盘上的 ZIP/已下载完整的 PART，不格式化、不重复下载 |
| 车机升级 | 自动进入 USB Upgrade，依次校验、安装、激活；已完成的阶段自动跳过 |
| 安装包检查 | auto/local 切到车机后检查实际挂载路径并核对 SHA256 |
| 从升级继续 | resume 直接从车机页面继续，不检查包文件、不切换 USB、不格式化 |
| 程控重启 | 激活完成并出现重启提示后下电 5 秒、上电，等待 60 秒再检测 ADB 和新的启动实例 |
| 版本校验 | 默认比较工程模式 QNX 版本后缀中的日期与电脑当天日期；不一致则停止 |
| 自动冒烟 | 版本校验成功后调用 ATS 工程的 pytest 冒烟用例，按数字从小到大串行执行 |
| 报告 | 保存升级事件、最后页面 XML、冒烟执行顺序、每个文件的日志/JUnit/Allure 结果和汇总 |

默认硬件配置：独立有线 ADB `3696ade`；USB 切换器 `COM14`，电脑端 3、车机端 2；电源 `ASRL13::INSTR`；U 盘根目录 `F:/`。更换设备时修改 `config.json`，同时核对 ATS 的 `page_objects/configs/dev.py`。

打开 PowerShell，进入脚本目录：

从云盘下载、自动升级、校验日期，然后执行 ATS 冒烟（格式化需要管理员权限）：

```powershell

```

U 盘已经接在车机端，直接从升级页面继续，完成后校验和冒烟：

```powershell
.\run.ps1 resume
```

车机已启动，从 ADB 检测开始，校验今天的日期，通过后执行冒烟：

```powershell
.\run.ps1 verify-adb
```

如果需要先等待 60 秒再检测 ADB，使用：

```powershell
.\run.ps1 verify-version
```

只做版本检查，不运行冒烟：

```powershell
.\run.ps1 verify-adb -SkipSmoke
```

`-SkipSmoke` 同样适用于 auto、local、resume 和 verify-version。

只查看实际冒烟顺序，不操作车机：

```powershell
.\run.ps1 smoke-plan
```

auto/local/resume 如需核对完整版本而非日期，可使用：

```powershell
.\run.ps1 resume -ExpectedQnx '完整目标QNX版本'
```

verify-adb/verify-version 固定使用日期检查。日期相同只证明编译日期一致，不代表完整版本号或 GAS 分类完全一致。

## 4. 冒烟执行规则

扫描 ATS 工程 `tests_scripts` 中符合以下命名的文件：

```text
test_smoke_test_数字.py
test_smoke_test_数字.子编号.py
test_smoke_test_数字_row行号.py
```

排序按主编号、子编号、行号依次比较数字，例如 `3 → 4 → 6 → 7 → 7_row5 → 7_row6 → 7.1 → 9 → 10`，不使用字符串排序。跨模块统一排序，同编号最后按相对路径稳定排序。编号缺失时不补造用例；`copy` 副本、`test.py` 和缓存不参与。

2026-09-15 曾实际识别并收集 42 个测试；collect-only 成功不等于实机测试通过。当前使用 ATS 正式执行器，由 ATS 调度用例、加载工程 fixtures 和管理报告，终端显示 ATS 的 run.log。旧独立 pytest 执行器的单文件子进程、插件隔离和 case_timeout 不适用于当前 ATS 页面执行方式。

任一失败、跳过、阻塞或零条用例结果都不能视为全部通过。停止用例请使用 ATS 页面停止按钮；Ctrl+C 仅停止终端监看。

## 6. 查看结果与排查

升级日志位于 `logs/<本次时间>/events.jsonl`，页面记录为 `last_ui.xml`。ATS 冒烟报告位于 ATS 工程的 `usbupdate/logs/.../smoke/`：

- `order.json`：本次用例执行顺序。
- `USB_Smoke.set`：带勾选状态的 ATS 测试集。
- `ats-request.json`、`ats-started.json`、`ats-result.json`：提交、接收及 ATS 最终结果。
- `ats-report/run.log`：ATS 实时日志。
- `ats-report/allure-results`、`ats-report/reports`：ATS 生成的报告。

`VERSION_DATE_VERIFIED` 表示日期校验通过；`VERSION_VERIFIED` 表示完整版本校验通过。`ATS_SUBMITTED` 只说明已提交，`ATS_COMPLETE` 只说明收到结果；必须同时检查结果 status=complete、total>0、passed=total 且无失败/跳过/阻塞/错误，才表示冒烟全部通过。

日期错误时不会启动冒烟；查看日志的预期日期、实际日期及完整 QNX 版本。冒烟失败时先查看 ats-result.json，再查看 ATS 页面与 run.log。日志里的“已收集测试”不等于实际冒烟通过。

旧分阶段命令 login/plan/connect/cloud/prepare/upgrade/verify 保留用于排查，不作为自动冒烟入口。推荐使用以上 auto/local/resume/verify-adb/verify-version。
