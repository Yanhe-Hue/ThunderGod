# 环境、依赖、接线与配置说明

本文依据当前脚本编写，适用于迁移部署、首次配置和故障排查。配合《功能与使用说明.md》使用。当前没有锁定依赖版本的 requirements.txt；不要把普通 Python 环境当作已经具备 AutoCar 驱动的 ATS 环境。

## 1. 电脑与运行环境

| 项目 | 要求与用途 |
|---|---|
| 操作系统 | Windows 桌面环境；建议沿用当前 Windows 10/11 64 位测试电脑。脚本调用 Windows 卷管理、PowerShell、盘符和图形选择框，不支持直接在 Linux、WSL 或无桌面服务器运行完整流程 |
| PowerShell | 保留系统 Windows PowerShell（powershell.exe），格式化脚本依赖 Get-Volume/Get-Partition/Get-Disk/Format-Volume；运行入口为 run.ps1 |
| Python | Python 3.10+，优先使用 ATS 自带、已安装 AutoCar 的解释器；需要 tkinter/Tcl/Tk 支持本地选包窗口 |
| 当前解释器 | `C:/Users/TS/AppData/Roaming/iatset/venv/Scripts/python.exe`；run.ps1 默认使用它，不存在则报错，不会自动切到其他 Python |
| 桌面交互 | 首次云盘扫码、GAS/no_gas 选择、本地包选择、ATS 页面需要登录到 Windows 的可交互桌面 |
| 权限 | auto 格式化需要管理员权限；USB 卷锁定/安全弹出也需要相应权限。拒绝访问时检查管理员权限及占用盘符的程序 |
| 磁盘空间 | U 盘必须容纳完整升级包；本地复制保留旧包时需额外空间。日志持续增长，压测前预留日志空间并自行归档，不设自动清理期限 |
| 网络与时钟 | 云盘模式需能访问创达云盘并具备群组目录权限；安装依赖需访问对应软件源。电脑日期必须正确，连接时车机与电脑时间默认允许偏差 120 秒 |

可在当前 PowerShell 设置解释器（路径按实际安装修改）：

```powershell
$env:AUTOCAR_PYTHON = 'C:/Users/TS/AppData/Roaming/iatset/venv/Scripts/python.exe'
& $env:AUTOCAR_PYTHON --version
```

这只影响当前终端及子进程；新终端需重新设置，或在 Windows 用户环境变量中保存。仅激活其他 venv 不会覆盖 run.ps1 的默认解释器。

## 2. 软件依赖与按模式区分

| 依赖 | 何时需要 | 配置/来源 |
|---|---|---|
| AutoCar SDK | USB 切换和电源控制 | 使用现有 ATS/AutoCar 环境，不要安装网络上同名但无关的包 |
| ADB / Android Platform Tools | 升级、读取 UI、日期核验 | `config.json` 的 adb 可填完整路径或 PATH 中的 adb |
| Android USB 驱动 | 独立有线 ADB | Windows 能识别车机，adb devices -l 显示 device，不能是 unauthorized/offline |
| 串口及电源驱动 | COM14 USB 切换器、ASRL13::INSTR 电源 | 使用设备厂家/现有 ATS 配套驱动及其 VISA/串口后端；具体驱动版本由设备型号决定，脚本不自动安装 |
| tkinter | local、stress 首次选择安装包 | Python 安装中的 Tcl/Tk 组件，不通过 pip 安装 tkinter |
| Playwright + Microsoft Edge | check 的云盘登录、auto/cloud/login | setup.ps1 -InstallCloud 安装 Python playwright；默认启动电脑已安装的 Edge，浏览器通道 msedge |
| uiautomator2 | ADB uiautomator dump 失败时的 UI 读取后备 | 当前 ATS 占用 UiAutomation 服务的场景会使用它，部署建议确保已安装；需要其设备端服务可正常运行 |
| VS Code + AI Test Studio | smoke，以及默认升级/日期校验后的冒烟 | 当前工程使用 ThunderSoft.AITestStudio，现场已有版本 0.10.2；不是所有版本均经过兼容验证 |
| USB Upgrade ATS Bridge | 将冒烟交给 ATS 页面 | 本工程提供 1.0.1 VSIX，声明 VS Code >=1.75；更新后执行 Developer: Reload Window |
| pytest、allure-pytest 及用例自己的依赖 | ATS 冒烟用例 | 使用 ATS 工程环境，保留 tests_scripts、page_objects、conftest.py 及工程设备配置；仅安装 pytest 不等于工程所有用例依赖齐全 |

`stress` 是独立模式，不调用 ATS 冒烟，也不使用云盘登录和 Edge。`local` 不需要云盘会话。二者直接运行的入口没有调用 `check`；**单独执行 check 时仍会要求 AutoCar、Playwright、ADB 并登录云盘**。因此只跑本地压测无需为了启动压测先扫码。

`resume` 和 `verify-* -SkipSmoke` 不需要 ATS 页面。auto/local/resume/verify-* 默认在校验通过后运行冒烟，可用 `-SkipSmoke` 关闭；stress 无论配置如何都关闭冒烟。运行 `smoke` 时保持 `smoke.enabled=true`。

安装公开的辅助依赖（使用正确的 AutoCar 解释器）：

```powershell
.\setup.ps1 -InstallCloud
& $env:AUTOCAR_PYTHON -m pip install uiautomator2
```

若 ADB 尚未安装：

```powershell
.\setup.ps1 -InstallAdb
```

该命令下载官方 Platform Tools 到 `tools/platform-tools`；随后手动把 config.json 的 adb 改为 `tools/platform-tools/adb.exe`。setup 只在不存在时创建 config.json/packages.json，不覆盖已有配置，也不负责安装 AutoCar、电源驱动、ATS 或 Edge。

## 3. 硬件接线与车机前提

| 设备 | 当前接线/地址 | 必须满足 |
|---|---|---|
| U 盘切换器 | 控制口 COM14；USB3 接电脑，USB2 接车机 | 配置与物理接线一致；SDK 返回 success 且 response_port 等于目标通道；回读成功后还会检查实际枚举 |
| U 盘 | 电脑端盘符 F:/；最终文件 F:/USB_UPDATE/Update.zip | Windows 识别为可移动盘、可写；auto 仅格式化单分区、USB 总线、非启动/系统/只读磁盘为 exFAT；local/stress 不格式化，需事先准备车机可读取的文件系统，建议 exFAT |
| 程控电源 | ASRL13::INSTR | 已按车机要求配置正确电压/限流并接线；脚本只控制输出开关，不设置电压或电流 |
| ADB | 独立数据线，当前序列号 3696ade | 切换升级 U 盘时仍可访问车机；已开启调试并授权电脑；不能使用 IP:端口 的无线 ADB |
| 车机软件 | USB 更新应用和 ThunderSoft 工程模式 | 应用组件、按钮英文文字及 resource-id 与配置一致，界面允许自动启动、读取层级和点击 |

AutoCar 适配层使用 `AT()`、`at.usb_switch(port=..., usb_port=...)`、`at.power_open(resource)` 和返回对象的 `set_output(on=False/True)`。SDK 必须支持这些方法及成功回读字段。电源下电默认 5 秒，然后上电；若恰好在下电期间手动停止，脚本不会隐式补发上电，需要人工确认电源状态。

车机 ADB shell 还需支持时间读取、UI dump/input/am start、启动状态及 boot_id 读取、升级包挂载位置读取与 SHA256 检查。升级包必须是与目标设备匹配的完整包；local/stress 可选择 ZIP 或下载完整的 PART，但仍须通过 ZIP CRC 检查，最终使用 Update.zip。

压测要求车机支持同一安装包重复升级。若系统拒绝重复版本，或页面停留在旧的安装/激活完成状态，脚本会停止，不把旧结果算作新一轮成功。

## 4. config.json 完整字段说明

以随工程提供的 `config.example.json` 为完整模板。路径建议写 `F:/` 或 `D:/目录`；如写反斜杠，JSON 中必须写双反斜杠。不要直接用局部配置片段覆盖整个文件。`-Config '其他配置.json'` 可选择配置；相对路径按 run.ps1 所在目录解析。

| 字段 | 示例/默认 | 含义 |
|---|---|---|
| adb | adb | ADB 命令或完整路径，本机已有 `C:/Users/TS/Downloads/adb/adb.exe`，换电脑需核对 |
| usb_serial | 3696ade | adb devices -l 中目标车机序列号 |
| wired_adb_independent | true | 确认 ADB 为独立有线连接；仅改布尔值不能替代实际接线 |
| usb_root | F:/ | 明确的 U 盘根目录，不能填 USB_UPDATE 子目录 |
| variant | gas | gas 或 no_gas；auto/cloud 可弹窗选择或用 -Variant 覆盖 |
| today_only | true | 云盘/清单选择只接受当天构建；false 可选择最新旧包，但后续默认日期校验仍与当天比较 |
| package_manifest | packages.json | 云盘生成及旧分阶段模式使用的包清单 |
| download_token_env | 空字符串 | 旧清单 URL 下载方式读取的令牌环境变量名称；不是云盘扫码登录配置 |
| max_clock_skew_seconds | 120 | ADB 连接时允许的车机与电脑时间差 |
| validation_timeout | 1800 | 等待包校验完成的秒数 |
| flash_timeout | 3600 | 等待安装完成的秒数 |
| activation_timeout | 600 | 等待激活完成的秒数 |
| boot_timeout | 600 | 重启后检测启动就绪的超时秒数 |
| power.resource | ASRL13::INSTR | 程控电源资源名，换设备需按实际发现结果设置 |
| power.off_seconds | 5 | 下电等待秒数，必须大于 0 且不超过 300 |
| usb_switch.port | COM14 | USB 切换器控制串口 |
| usb_switch.pc_usb_port | 3 | 电脑通道，整数 1～4 |
| usb_switch.car_usb_port | 2 | 车机通道，整数 1～4，不能与电脑通道相同 |
| usb_switch.enumeration_timeout | 60 | 切换后目标端设备枚举等待秒数 |
| smoke.enabled | true | 是否调用冒烟；stress 始终覆盖为 false |
| smoke.project_root | ATS 工程根目录 | 含 tests_scripts 的根目录，不是 usbupdate 子目录；迁移工程必须修改 |
| smoke.case_timeout | 1800 | 旧独立 pytest 执行器参数；当前 ATS 页面调度不使用此字段控制单用例超时 |

重启上电后等待 **60 秒再检测 ADB** 固定在当前代码中，不是 config.json 的配置项。verify-adb 不加这段等待，verify-version 会等待。压测没有轮数和间隔参数，一直运行到 Ctrl+C 或异常。

### 包清单与运行记录

setup 在缺少 packages.json 时创建空清单 `[]`。auto 由云盘生成真实清单，local/stress 从所选包生成记录，不要求人工填写 SHA256。旧分阶段模式使用的清单字段为 folder、name、build_date、source、sha256、expected_qnx，需真实有效的数据。prepared_package.json 为最近准备的包记录；logs 为运行结果，不要把旧完成标记当作本次成功。config.example.json 是首次安装必需的配置模板，予以保留。

## 6. 首次部署顺序与验证

1. 将整个 usbupdate 目录放入 ATS 工程（只做压测也可以独立放置），配置硬件接线和驱动。
2. 设置 AUTOCAR_PYTHON；运行 setup.ps1 初始化缺失的配置，按需安装云盘或 ADB 依赖。
3. 编辑 config.json：优先核对 adb、usb_serial、usb_root、电源资源、切换器端口、ATS 根目录。不要覆盖用户已有配置。
4. 核对电脑/车机时间、USB 盘符、ADB 授权、车机应用版本及包日期。
5. 使用云盘时执行 `.\run.ps1 check` 并扫码；出现 ENVIRONMENT_CHECK_PASSED 才表示这一检查完成，但不代表电源、USB 路由、升级和用例已经验证通过。
6. 需要冒烟时安装/重载 ATS 连接扩展；`.\run.ps1 smoke-plan` 可查看用例顺序，不实际测试。
7. 按实际任务执行下表中的命令。

| 命令 | 行为 |
|---|---|
| .\run.ps1 auto | 云盘选包、格式化 U 盘、升级、重启、日期校验、冒烟 |
| .\run.ps1 local | 本地选包后升级、校验、冒烟，不格式化 |
| .\run.ps1 resume | U 盘已在车机侧，从升级页面继续，不检查安装包文件 |
| .\run.ps1 verify-adb -SkipSmoke | 已开机，从 ADB 连接开始核对日期 |
| .\run.ps1 verify-version -SkipSmoke | 先等待 60 秒，再连接 ADB 核对日期 |
| .\run.ps1 smoke | 仅执行 ATS 冒烟，需 smoke.enabled=true |
| .\run.ps1 stress | 首次选包后无限循环升级、重启、等待 60 秒、ADB/日期核验；不执行冒烟，Ctrl+C 停止 |

读取依赖/配置的检查命令（不操作电源或切换 U 盘）：

```powershell
& $env:AUTOCAR_PYTHON -c "import autocar, tkinter, uiautomator2; print('基础依赖可导入')"
& $env:AUTOCAR_PYTHON -c "import playwright; print('云盘依赖可导入')"
& $env:AUTOCAR_PYTHON -m json.tool config.json > $null
& 'C:/Users/TS/Downloads/adb/adb.exe' devices -l
```

ADB 路径按实际配置替换。导入成功仅说明 Python 能找到依赖，不验证设备通信。

## 7. 常见报错与对应环境项

| 现象 | 优先检查 |
|---|---|
| AutoCar Python not found / 未安装 AutoCar | AUTOCAR_PYTHON 是否指向真正的 ATS 解释器 |
| 缺少云盘自动化依赖 | 用同一个解释器执行 setup.ps1 -InstallCloud，而不是在其他 venv 安装 |
| 无法启动 msedge / 登录失效 | Edge 安装、云盘网络和权限，重新 check 登录 |
| ADB 未就绪 / unauthorized | 独立数据线、驱动、车机授权、usb_serial |
| 时间偏差过大 | 电脑及车机时钟同步，默认偏差不能超过 120 秒 |
| USB 回读成功但 F 盘不出现 | 物理 PC=3/CAR=2 接线、实际盘符、枚举超时；串口回读不是 U 盘挂载成功 |
| 车机未挂载目标包或哈希不匹配 | 车机端 USB 连接、文件系统、USB_UPDATE/Update.zip、包完整性 |
| 格式化/安全弹出失败 | 管理员权限、占用该盘的程序、是否可移动 USB 单分区磁盘 |
| UiAutomation already registered | uiautomator2 后备依赖及设备服务；查看 COMMAND_FAILED/UI_DUMP_FALLBACK 日志 |
| 日期不符 | 包实际 QNX 日期和电脑日期；stress 使用本次启动日，不自动改成实际读到的版本日期 |
| ATS 未接收任务 / aborted total=0 | 打开正确根工程、信任工作区、启用扩展、安装 1.0.1 后重载、测试集确实有勾选用例 |

本次文档依据代码核对，不等于新电脑已经完成实机验收。压测逻辑已完成本地模拟测试，未因此声明无限循环实机刷写通过。
