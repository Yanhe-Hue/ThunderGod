# 独立 U 盘压测

## 冒烟失败继续压测（当前规则）

双版本压测在升级、版本核验成功后执行所选冒烟。ATS 正常结束时，不论用例通过、失败、阻塞或跳过，均进入下一轮；失败不会被改成通过。手动中断、ATS 未接收/异常退出/取消，以及升级或版本核验失败仍停止，避免测试未结束时再次刷写。

每轮结果保存在 stress_summary.json：冒烟失败轮次的 status 为 completed_with_smoke_failures，upgrade_status 为 passed，smoke 内记录原因、ATS 原始统计、failedScripts 及报告路径。总计字段 completed_rounds、fully_passed_rounds、smoke_failed_rounds 分别表示已完成、全部通过和冒烟未通过轮数；每轮日志同时记录 STRESS_SMOKE_FAILED_CONTINUING。ATS 自己的详细用例报告不变。

这仅改变独立双版本压测；主升级 auto/ci-once 的冒烟失败仍返回失败。下文旧版“冒烟失败停止”的描述以本节为准。


## 启动时选择冒烟用例（当前默认）

运行 run_stress.ps1 后先弹窗列出 ATS 原 tests_scripts 的编号冒烟用例，支持单选、Ctrl/Shift 多选、选择模块（可追加多个）、全选和清空。点击“确认用例并开始压测”后才操作硬件，取消不会刷写。窗口预选配置中原第4条用例，本次选择不会永久覆盖该列表；本次每轮复用选定组。

由 smoke.select_before_stress=true 开启，case_directory=tests_scripts 指向原工程；设为 false 则按 case_files 固定执行。用例保持原位置，继承原 conftest.py。只列出主升级同样命名规则的编号冒烟文件，按数字顺序执行；选择结果保存在本次 stress_summary.json 的 selected_cases。

## 当前台架验证：只调用原工程第 4 条冒烟

为保留原 conftest.py 的设备 fixture，压测支持 smoke.case_files 指定原始文件，不复制用例。当前 D 盘实际配置使用：

```json
"smoke": {
  "enabled": true,
  "case_directory": "tests_scripts",
  "case_files": ["tests_scripts/桌面启动器/test_smoke_test_4.py"]
}
```

project_root 保留真实 ATS 工程根目录。配置只影响使用该配置文件的压测/冒烟，不改主升级 config.json 的完整冒烟计划。每轮 A/B 升级校验后，由 ATS 执行这一条原始用例；case_files 路径必须真实存在且位于 case_directory 下，不会在文件缺失时默默执行全部用例。以后要恢复整个原目录冒烟，删除 case_files 字段；要恢复新目录方案则改回 case_directory=usbupdate/smoke_cases 并配置好 fixture。

原阻塞日志已确认是 `fixture 'at' not found`，搬到新目录后没有继承 tests_scripts/conftest.py，不能把该阻塞当成升级失败或冒烟通过。


## 新模式：U 盘 A/B 交替，每轮执行冒烟

当前新增 `stress.mode="usb_pair_smoke"`。不用云盘，不格式化、不缓存到电脑。先把两份完整原包放在 U 盘上，例如 `F:/versions/A.zip` 和 `F:/versions/B.zip`；不能把原包放在 `F:/USB_UPDATE/` 中。每轮保留原包，将目标包复制到 `F:/USB_UPDATE/Update.zip`，先写临时文件、校验 SHA256，再替换正式文件。U 盘需有额外空间容纳临时包。

在 `usb_stress_config.json` 中将 stress 设置为以下格式，路径与日期必须替换成真实信息：

```json
"stress": {
  "mode": "usb_pair_smoke",
  "packages": [
    {"path": "F:/versions/A.zip", "expected_date": "2026-09-14"},
    {"path": "F:/versions/B.zip", "expected_date": "2026-09-15"}
  ]
}
```

也可 packages=[]，首次弹窗依次选择 U 盘上的 A、B，但包内必须能提取 QNX 日期。默认按每包日期核验，标准与主升级相同；若两个版本日期相同，仅比较日期无法证明版本差异，应为每个包增加真实 `expected_qnx` 完整版本号，届时严格比较完整版本。

把真实冒烟用例放在 `usbupdate/smoke_cases/`（支持模块子目录），命名规则与主升级一致，按数字排序。将原目录所需的 conftest.py/资源依赖一并配置；原 tests_scripts 下的 fixture 不会自动继承到新目录。本目录未擅自复制或编造测试用例；没有用例会在操作硬件前停止。

安装 `ats_bridge/usbupdate-ats-bridge-1.0.2.vsix` 并在 VS Code 执行 Developer: Reload Window。保持 ATS 根工程打开。该版本支持从新目录提交用例，旧版扩展会拒绝新路径。

运行命令不变：使用 ATS Python 执行 `usb_stress.py`。流程为 A 升级→重启等待120秒→版本校验→ATS冒烟→B升级→校验→冒烟→循环。每次显示当前轮数和累计成功数，全部通过才进入下一轮；失败停止，Ctrl+C 手动停止。ATS 冒烟必须有实际执行用例且全部通过、无失败/跳过/阻塞。冒烟取证由 ATS 管理，升级异常沿用日志/截图。

以下 cloud/local_single/local_pair 为保留的旧模式，仍不执行冒烟；新需求使用 usb_pair_smoke。


入口为 usb_stress.py，配置为 usb_stress_config.json。此配置包含完整设备、云盘及 UI 设置，不读取 config.json；初始设备配置从当前工作区配置复制，使用前核对 adb、usb_serial、usb_root、电源及切换器。

入口复用同目录 auto_update.py、usb_update.py、hardware.py、volume.py、cloud_download.py、package_metadata.py 等模块，因此迁移时保留整个 usbupdate 目录，不能仅复制这两个文件。运行环境和驱动要求见《环境依赖与配置说明.md》。不调用 ATS 冒烟，也不需要打开 ATS 执行页面。

## 运行

在 usbupdate 目录打开 PowerShell：

```powershell
$pythonPath = 'C:/Users/TS/AppData/Roaming/iatset/venv/Scripts/python.exe'
& $pythonPath .\usb_stress.py
```

无需轮数参数，持续运行，Ctrl+C 停止。重启后等待 120 秒再检测 ADB，日期校验通过才进入下一轮，失败立即停止。停止脚本不会强行断电或中断车机自身刷写；若在下电期间停止，需人工确认电源状态。

## 选择三种模式

只修改独立配置里的 stress 对象，保留其余设备和 UI 配置。

### 本地单包循环

默认配置为此模式。packages 为空时，启动后弹窗选择一次；若包内无法读取明确 QNX 日期，填入实际日期和路径再运行：

```json
"stress": {
  "mode": "local_single",
  "cache_dir": "stress_cache",
  "packages": [{"path": "D:/firmware/A.zip", "expected_date": "2026-09-15"}],
  "cloud_expected_date": ""
}
```

路径、日期为填写格式，须替换为真实值。电脑或 U 盘上的完整 ZIP/PART 都可选择。每轮使用同一个包，不重新下载、不格式化。

### 本地 A/B 两包交替

```json
"stress": {
  "mode": "local_pair",
  "cache_dir": "stress_cache",
  "packages": [
    {"path": "D:/firmware/A.zip", "expected_date": "2026-09-14"},
    {"path": "D:/firmware/B.zip", "expected_date": "2026-09-15"}
  ],
  "cloud_expected_date": ""
}
```

顺序为 A → B → A → B，不自动判断当前车机版本来改变起始顺序。也可以 packages=[]，依次弹窗选 A、B，但必须能从包内提取日期。两个包必须有不同 SHA256；车机必须允许相应升级、降级及重复刷写。若被车机拒绝或残留旧完成状态，脚本停止，不假定本轮成功。

两包先缓存到电脑，之后原子替换 U 盘 USB_UPDATE/Update.zip，不每轮追加备份文件，不格式化 U 盘。U 盘需留有额外空间容纳当前包和下一包的临时文件。

### 云盘下载后循环

将 mode 改为 cloud；顶层 variant 填 gas 或 no_gas，today_only 和 cloud.path 继续控制构建选择。此独立入口按配置选分类，不弹出 GAS 分类选择框。

首次或登录失效时，先运行：

```powershell
& $pythonPath .\usb_stress.py --login
```

该命令只检查环境、扫码登录，保存配置的 cloud.auth_state，不开始压测。然后正常启动 usb_stress.py。

cloud 模式只在启动时拉取一次包：找到目标构建后格式化配置 U 盘为 exFAT，下载到 USB_UPDATE/Update.zip，再缓存到电脑，后续复用同一包。**格式化会清除该 U 盘全部文件，需要管理员权限**。下次重新启动 cloud 模式会重新选包和下载。

## 日期与缓存

日期来源按优先级：手动 expected_date（云盘为 cloud_expected_date）→ 包内明确 QNX 版本日期 → 仅云盘模式可使用所选构建目录日期。云盘目录日期可能与 QNX 编译日期不同，如不一致应填写该包真实 QNX 日期，不能拿刷完后读到的日期自动当预期。

本地包不能提取日期且未填写时，在刷写前停止。日期按每个包固定，跨午夜不变，不强制等于运行当天。同一天的不同版本可以交替，但日期校验不能区分同一天的完整版本；SHA256 只证明传输的是目标文件，不能代替安装后完整版本核验。

cache_dir 必须在电脑磁盘，不能在目标 U 盘；默认 stress_cache，每次启动创建独立子目录。预留电脑空间容纳所有包；缓存保留供排查，停止运行后可人工清理对应子目录。每轮重新核对缓存与 U 盘包的 SHA256。

每次运行生成 logs/时间/stress_summary.json，记录 A/B 包哈希、对应日期、轮次、耗时、状态及每轮日志路径。准备阶段失败也会保留原因。无限运行的日志持续增长，需要预留空间。

原有 .\run.ps1 stress 保留旧入口；使用上述独立入口才读取 usb_stress_config.json 并支持本地 A/B 与云盘压测。只完成模拟测试，不代表实机循环刷写通过。
